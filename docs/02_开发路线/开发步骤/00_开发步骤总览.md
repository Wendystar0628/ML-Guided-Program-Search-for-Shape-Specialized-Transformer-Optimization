# Transformer GPU Kernel 项目开发步骤总览

> 步骤文档描述开发预期，不记录当前完成度。项目状态直接以仓库代码、测试与 GPU 结果为准。

## 开发主线

1. 固定官方 Benchmark、14 个 Shape、公共接口和正确性条件。
2. 对 `official_01`–`official_13` 建立默认 Paired GPU Benchmark，对 Shape 14 建立独立 `benchmark-streamed`。
3. 按 Batch、Width、Head 和 Sequence 分析瓶颈，接入少量通用算法族。
4. 使用短测筛选与 Formal 复测把赢家绑定到具体 GPU 与 Shape。
5. 用普通 Sweep 观察 Shape 1–13 的 Speedup、几何平均和路由回归；单独观察 Shape 14 的 Target-only 流式结果。
6. 整理可直接运行的 Public Repository、README、技术报告和 Demo。
7. 性能主线稳定后，在同一 Runner 上建设专用 Agent 运行时与调优闭环。

## 1. 测量基础与实现接口

完成官方快照、共享 Shape 事实源、`UserOptimizedTransformer`、权重对齐、Comparator、GPU Event 计时、普通 Paired Benchmark、独立 `benchmark-streamed`、Fresh Worker 和最小持久化。详见 [01_测量基础与实现接口.md](./01_测量基础与实现接口.md)。

## 2. 核心 Workload 性能优化

使用 Hardware Profile 和 Shape 分析选择通用 SDPA、CUDA Graph、Fused Norm、Mixed-FP16 Attention/Core 与严格 Shape Guard 的自主 Triton Fusion 等少量候选；`safe` 只作为不可部署的内部诊断与 Fallback 路径。Shape 14 使用 `B=1` provisional Comparator，并在显存守卫下实测选择 Timing Microbatch 与内存高效 Attention 后端。详见 [02_核心Workload性能优化.md](./02_核心Workload性能优化.md)。

## 3. 跨 Workload 优化与收敛

在目标 GPU 上串行执行候选，Smoke 只检查正确性与实际执行，所有通过者交给 Formal 决定可晋升路由。精确路由、Fallback 和已验证设备包共同形成跨硬件执行闭环。详见 [03_跨Workload优化与收敛.md](./03_跨Workload优化与收敛.md)。

## 4. 最终校验与提交

复核官方入口、普通 Sweep、Shape 14 独立流式结果、GPU 正确性、清晰代码结构和可重复命令。对外交付为 Public GitHub Repository、Devpost 说明、技术报告和 Public YouTube Demo。详见 [04_最终校验与提交.md](./04_最终校验与提交.md)。

## 5. Agent 运行时与设备校准

建设一个专用 CLI Agent，支持 DeepSeek API 配置、Shell/PowerShell、文件工具、用户打断、状态保存与多轮上下文压缩。Agent 复用 Runner 的 Probe、候选和校准能力。详见 [05_Agent运行时与设备校准.md](./05_Agent运行时与设备校准.md)。

## 6. Agent 调优闭环与扩展

Agent 从硬件画像、Shape、实测结果与必要 Profile 中选择下一步，通过可控 Patch 和真实 GPU 反馈迭代。确定性 Runner 仍负责测量、正确性和路由发布。详见 [06_Agent调优闭环与扩展.md](./06_Agent调优闭环与扩展.md)。

## 稳定目录结构

```text
TikTok_2026/
├── official/                 官方 Benchmark、Shape 与快照身份
├── solution/                 Transformer、Execution Plan、Dispatch 与 Kernel
│   └── kernels/              当前 Attention、Norm、QKV 等执行原语
├── runner/                   Probe、测量、校准、流式执行与发布服务
├── verified_hardware/        已验证设备的 Profile、Route、Manifest 与入口
│   └── <device_id>/
├── results/
│   ├── final/                每个设备唯一的对外最终结果
│   └── intermediate/         被 Git 忽略、可随时重建的本地过程结果
├── tests/                    合同、控制面、路由、Kernel 与真实 GPU Smoke
├── docs/
│   ├── 01_赛题规则/
│   ├── 02_开发路线/
│   ├── 03_Agent系统/
│   └── 04_最终交付物/
├── video/                    演示材料工作区；成品通过公开链接交付
├── policy_registry.py        Policy 唯一事实源
├── route_contracts.py        Route 与 Bundle 合同
├── torch_transformer_benchmark.py
└── environment_check.py
```

需要新增执行文件时先归入以上职责目录。精确文件清单直接以仓库为准，不在开发文档复制第二份容易过期的逐文件镜像。只在开始 Agent 实现时创建 `agent/`，不预建空目录。
