# 4. 最终校验与提交

> 最终阶段使用少量强证据说明官方兼容、正确、更快且可复现。不把开发过程、过时结果或大量内部校验记录搬进提交材料。

## 1. 最终 Solution

- 根目录官方兼容入口可直接运行。
- `UserOptimizedTransformer` 保持官方构造、权重和 Forward 合同。
- 完整 Causal Mask 不在模型构建期或普通执行路径中无条件物化。
- 可部署 Policy 包含通用 SDPA、CUDA Graph、Fused Norm、Mixed-FP16 Efficient 与 Mixed-FP16 cuDNN 等经过真实 Shape 验证的路径；`safe` 是不可部署的内部诊断与 Fallback 路径。
- 无效、未实现或无官方 Shape 用途的旧 Kernel、Candidate、Route 和说明被删除。
- 代码注释使用英文，入口和主线文件能被首次审阅者快速找到。

## 2. 必要测试

### 快速结构与控制面

- 官方 Benchmark 与 Shape Hash；
- Workload Loader 从同一事实源精确加载普通 1–13 与独立 Shape 14；
- Policy/Candidate Registry 一致；
- Execution Plan 与 Dispatch Fallback；
- Result/Route/Bundle 契约；
- Resident/Batch-streamed 执行计划、Timeout 和用户中断。

### 真实 GPU

- 主要 Policy 真实命中，输出 Shape/Dtype/Device 正确；
- 官方 Comparator 使用 `rtol=0.02`、`atol=0.002`通过；
- CUDA Event 延迟为有限正数；
- 每个可晋升 Route 有同一 GPU 上的 Baseline 与 Solution Formal 对比；
- Shape 14 以 `B=1` 建立 provisional 正确性证据，并用实测选出的 Timing Microbatch 跑完整逻辑 Batch，报告 Target-only 结果；
- 默认 1–13 Shape Sweep 没有被遗漏的回归，Shape 14 独立流式入口可以完整结束。

## 5. 技术报告

报告的主线为：

1. 官方 Transformer 和 Shape 中隐含的不同瓶颈；
2. GPU 硬件特征如何影响候选优先级；
3. 通用 SDPA、CUDA Graph、Fused Norm、Mixed-FP16 Efficient/cuDNN 和 Shape 14 Batch Streaming 分别改变了哪一段执行链；
4. 为什么使用离线实测和精确路由，而不是在 Forward 内动态试错；
5. 正确性和计时协议；
6. 逐 Shape 数字、瓶颈迁移和与预期的差距；
7. AI Skills/Tools 在分析、候选设计、代码和测试中的具体作用；
8. 局限与有价值的后续方向。

Insight Card 可以用简洁表格呈现：观测、机理解释、候选、实测结果、决策。它是技术叙事，不是一套复杂实验数据库。
