# 1. 测量基础与实现接口

> 本步骤建立官方 Shape 与所有后续优化共用的最小执行通道。

## 1. 官方合同

- `official/torch_transformer_benchmark.py` 保存唯一 PyTorch Benchmark 快照。
- `official/test_shapes.json` 保存 `official_01`–`official_14`；普通 Benchmark/Sweep 使用 1–13，Shape 14 由独立 `benchmark-streamed` 使用。
- `official/snapshot.json` 绑定 Benchmark 和 Shape 文件身份。
- 根目录 `torch_transformer_benchmark.py` 作为简明的官方兼容入口。
- `UserOptimizedTransformer(config)` 与 `forward(x, valid_token_mask)` 保持官方接口，输出为 `[B,S,D]`。
- Baseline 与 Solution 使用相同权重、输入、Mask、Device 和 Dtype。

`QKV Dim` 在 Runner 合同中使用官方名称，在 Transformer 实现内映射为 `d_model`。Shape 和 Measurement Protocol 分开：Shape 不携带自造 Dtype、Padding 或组权重。

## 2. Workload Loader

Runner 从 `official/test_shapes.json` 构建 `official_transformer_v1`，不维护第二份 Shape 列表。

基本验证包括：

- ID 唯一且顺序稳定；
- 维度为正整数；
- `qkv_dim % heads == 0`；
- Causal 字段与官方表一致；
- 普通集合包含 1–13，流式入口精确选择 Shape 14，二者顺序与身份都来自同一文件；
- 全部内容和顺序参与 Workload Hash。

单 Case、整组 Sweep、Profile、Tune、Calibrate 与 Verified Runner 使用同一 Loader。

## 3. Correctness

正确性直接复用官方语义：

- `rtol=0.02`；
- `atol=0.002`；
- 绝对条件或相对条件通过；
- 通过多个可重现 Accuracy Trial 汇总最大误差与失败元素数；
- 记录实际 Execution Path，避免把 Fallback 解释为专用 Policy 成功。

Resident Shape 使用完整 Baseline Comparator。Shape 14 的 Dense Baseline 无法在消费级显存中驻留，因此当前由一个完整 `B=1` 样本的 Query-block Reference 检查流式目标路径，并明确标记为 `provisional`。该证据只证明当前输入、权重和协议下的数值一致性，不替代官方最终 Golden Output 验证。

## 4. GPU 计时

- 正式数字只使用 CUDA Event 测量完整 Transformer Forward。
- Baseline 可执行时，Baseline 与 Solution 交替测量，降低温度、频率和时间顺序影响。
- Warmup 、Repeats、Rounds、Dtype、TF32 与 Seed 位于 Protocol。
- 结果显式区分 `baseline_only`、`paired` 与 `target_only`。Shape 14 使用 Target-only Median/P90、峰值显存、Useful FLOPs 和 Achieved FLOP/s，不伪造 Baseline 或 Speedup。
- P90 用来观察稳定性，Median 用于主性能比较。
- Profiler 与 Microbenchmark 是瓶颈诊断，不代替完整逻辑 Workload 的端到端计时。

## 5. Fresh Worker 与 GPU 单写者

每个测量 Case 在独立 Worker 中创建模型、复制权重、Warmup、正确性检查和计时。Supervisor 管理 Timeout、Ctrl+C、Worker 异常和结果落盘。

正式 GPU 测量使用设备锁串行执行，避免并发 Candidate 污染延迟。路由与 Verified Bundle 发布使用单独包锁，完整生成后原子替换。

## 6. Workload Execution Plan

Runner 共享两种执行形态，但由两个清晰入口组织：

- 普通 `benchmark`/Sweep 使用 `resident`：Baseline、Solution 和 Comparator 都在单个 Worker 中完整驻留；
- `benchmark-streamed` 使用 `batch_streamed`：固定用 `B=1` 建立 provisional 正确性证据，再从逻辑 Batch 的正因子中筛选 Timing Microbatch，复用输入、输出和模型 Buffer，并用实测峰值守卫避免进入显存分页区。

`batch_streamed` 不改变单个样本内部的 Transformer 数学语义，也不是一个可部署 Policy。Runner 先淘汰 Comparator 或真实执行证据失败的候选，再对 Policy 与 Timing Microbatch 的有限笛卡尔积做串行短测；最终正式计时锁定同一 Execution Plan Fingerprint。运行计划同时决定适合长任务的 Warmup、Repeat、Round 与 Timeout。

## 7. 结果持久化

一次成功的中间 Run 保留：

- Run ID、时间、Case 与 Target；
- Shape 与 Measurement Protocol；
- 紧凑 Hardware/Runtime 身份；
- Correctness 汇总；
- Comparison Mode、可用的 Baseline/Solution Median、P90、Sample Count 和 Speedup；
- Useful FLOPs、Achieved FLOP/s、项目估算 MFU、逻辑算子流量、峰值显存，以及 Shape 14 的验证 Microbatch、Timing Microbatch 与 provisional Reference 范围；
- Requested Policy、Selected Policy、Observed Execution 与 Route Source；
- Official、Workload、Solution 和 Route Hash。

不保留原始每次 Sample、重复字段、完整 Traceback 或 Profiler Timeline。失败 Run 只保留已知身份、失败阶段和短错误。所有开发、Probe、Profile、Sweep、Tune 和 Calibration 产物都收口到同一个忽略上传的中间区域：

```text
results/intermediate/...
```

对外交付只保留一个当前文件：

```text
results/final/<hardware_id>.json
```

该文件按 Case 合并同一设备的有效 Formal 结论。Shape 1-13 保留 Paired Baseline/Solution、Speedup 和几何平均；Shape 14 保留 `target_only` 与 `provisional` 边界，不伪造 Baseline、Speedup 或几何平均贡献。每个 Shape 都保留 Latency、Achieved FLOP/s、项目估算 MFU、Peak Allocator Bytes 和 Logical Operator Traffic；最后一项只是当前算子边界的逻辑流量估计，不是实测 DRAM 带宽。

## 8. Runner 入口

- `probe`：采集硬件身份、运行栈和少量性能 Anchor。
- `benchmark`：运行 Baseline 或 Solution 的单 Case/默认 Sweep。
- `benchmark-streamed`：独立运行 Shape 14 的 Target-only Batch Streaming、provisional Comparator 与 Attention 后端筛选。
- `profile`：定位完整 Forward 的主要算子热点。
- `tune`：测量用户显式指定的候选，不发布路由。
- `calibrate`：用白盒粗排、Smoke、Formal 和晋升门禁构建当前 GPU 路由。

默认 Workload Set 是 `official_transformer_v1`，默认设备是 `cuda:0`。CPU 可以检查控制面，不生成性能结论。

## 10. 验收信号

- 官方快照和 Shape Hash 可重算；
- 默认 Sweep 精确加载 1–13，`benchmark-streamed` 精确加载 Shape 14；
- 正确实现通过、故意错误实现失败；
- CUDA Event 返回有限正数，各 Comparison Mode 下的 Median/P90/Speedup 与 Sample Count 自洽；
- Shape 14 使用 `B=1` 完成 provisional Comparator，并用实测选出的内存安全 Timing Microbatch 跑完完整逻辑 Batch，不物化完整 Attention Matrix；
- Shape 14 的内部 Reference 明确标记为 `provisional`，不会被当作正式路由晋升证据；
- Ctrl+C、Timeout、OOM 和 Worker 异常留下精简明确终态；
- 普通 GPU Sweep 汇报 1–13 Paired 结果与几何平均，Shape 14 的流式结果单独汇报，不混合成一个总分。
