# Transformer GPU Kernel 项目：允许与不允许的改造范围

> 依据官方赛题说明与 [`torch_transformer_benchmark.py`](../../torch_transformer_benchmark.py) 整理。
> 核心原则：**允许改变“怎么算”，不应改变“算什么”。**

## 一、允许的改造与调优

### 1. 执行方式优化
- `torch.compile`
- PyTorch SDPA（`scaled_dot_product_attention`）
- Triton Kernel
- CUDA Kernel
- Shape-specific Kernel / Dispatcher
- 不同 Workload 使用不同实现路径

### 2. 算子融合（Operator Fusion）
- Q / K / V Projection Fusion
- Scale + Mask + Softmax Fusion
- Attention 内部 Fusion
- Bias + GELU Fusion
- Residual + LayerNorm Fusion
- FFN 内部 Fusion
- 其他保持数学等价的 Kernel Fusion

### 3. GPU 执行参数调优
- Tile / Block Size
- `num_warps`
- `num_stages`
- Shared Memory 使用方式
- Register 使用与 Occupancy 调整
- Memory Layout / Coalesced Access
- Tensor Core 利用
- Kernel Launch 数量优化

### 4. 数值与精度策略
在通过官方 Correctness 检查的前提下，可尝试：
- FP32
- TF32
- FP16
- BF16
- 其他不会使最终输出超出误差要求的数值优化

### 5. 利用已有结构中的无效计算
- Causal Mask 已规定为无效的位置可跳过计算
- Padding Token 对应的无效计算可进行等价优化
- 不产生新的 Attention 稀疏模式

---

## 二、条件允许，但必须严格验证

以下优化可能改变内部数据组织或数值路径，但如果**数学语义保持一致、接口兼容、官方误差测试全部通过**，可以采用：

- 将三个 Q/K/V Linear 重组为单个 Fused QKV Projection
- 修改 Parameter Layout，并相应修改 `copy_model_weights()`
- 使用更激进的低精度或 Approximate Math
- 修改 Fusion Boundary
- 针对不同 Shape 选择不同 Kernel Family
- 使用硬件专用 Triton / CUDA 实现

判断标准：

1. **Same Function**：理论上仍计算同一个 Transformer。
2. **Same Contract**：保持官方 `forward(x, valid_token_mask)` 接口和 `[B, S, D]` 输出。
3. **Numerical PASS**：官方全部 Accuracy Trial 通过。
4. **Faster**：通过前三项后，再比较性能。

---

## 三、不应采用的改造

这些方案改变了官方定义的 Transformer 数学结构，应默认视为不符合本赛题目标：

### Attention 架构变化
- Sliding-Window Attention
- Local Attention
- Top-K Sparse Attention
- 随机稀疏 Attention
- Linear Attention
- 自行引入新的 Sparse Attention Pattern
- 将部分 Head 改成 Local / Sparse Attention
- MHA 改成 MQA / GQA

### Transformer 结构变化
- 减少 Transformer Layer 数量
- 删除 Attention Head
- 修改 Head 数量
- 缩小 Hidden Dimension
- 缩小 FFN Dimension
- GELU 改为 ReLU / SiLU 等其他激活函数
- 将 FFN 替换成 MoE
- 删除 Residual / LayerNorm
- 改变 LayerNorm 的位置或数学定义

### 模型近似与压缩
除非官方后续明确允许，否则不建议作为主方案：
- Weight Pruning
- Low-Rank Approximation
- Token Pruning / Token Dropping
- 结构化剪枝
- 通过修改权重或网络结构换取速度

这些方法的核心问题是：它们主要在改变模型，而不是优化同一模型的 GPU 实现。

---

## 四、最终判定原则

一个优化候选只有同时满足下面三个条件，才应进入性能比较：

```text
数学语义保持一致
        +
官方接口保持一致
        +
Correctness 全部通过
        ↓
才比较 Median Latency / Speedup
```

因此，本项目的优化边界可以概括为：

> **可以重新组织计算、融合算子、改变 Kernel、改变底层数据布局和硬件执行策略；不能把官方固定 Transformer 换成另一个更省计算但数学定义不同的 Transformer。**
