# Transformer GPU Kernel 改造边界

> 依据官方文字和 `official/torch_transformer_benchmark.py` 整理。原则是改变计算组织与 GPU 执行方式，保留官方 Transformer 的数学函数、权重和接口。

## 1. 允许的主线

- 为不同已公布 Shape 选择不同的等价 Kernel 或组合路径。
- 使用 PyTorch SDPA、`torch.compile`、Triton 或 CUDA。
- 融合 QKV Projection、Scale/Causal/Softmax、Attention、Bias/GELU、Residual/LayerNorm 或 FFN 内部边界。
- 调整 Tile、Block、Warp、Stage、Shared Memory、Register、Occupancy 与访存布局。
- 使用 Tensor Core、TF32 或其他精度策略，前提是通过官方 Comparator。
- 使用隐式 Causal 索引、Tiled/Online Attention 等方式避免无必要的 $S^2$ 中间张量。
- 重排 Parameter Layout，并通过配套权重复制逻辑保持与 Baseline 一致。

## 2. 候选进入性能比较的条件

1. `UserOptimizedTransformer` 保持官方构造与 `forward(x, valid_token_mask)` 接口。
2. 输出 Shape、Dtype 和 Device 符合官方合同。
3. 使用同一组权重和输入，通过 `rtol=0.02`、`atol=0.002` 比较。
4. 专用 Policy 实际执行，不把悄然 Fallback 记为候选成绩。
5. 收益使用完整 Transformer Forward 的 GPU 实测判断。

内部计算顺序或数值路径可以不同，官方 Comparator 和完整 Forward 计时共同决定候选是否有效。

## 3. 不使用的改造

- 将 Full/Causal Attention 换成 Sliding-Window、Local、Top-K、Random Sparse 或 Linear Attention。
- 将 MHA 改成 MQA/GQA，减少 Layer 或 Head，缩小 QKV/FFN 维度。
- 删除或移动 Residual/LayerNorm，替换 Exact GELU，或把 FFN 换成其他结构。
- Weight Pruning、Low-Rank Approximation、Token Dropping 或其他以修改模型函数换取速度的方法。
- 修改 Baseline、Comparator、官方 Shape 或计时方式来制造 Speedup。
- 使用 CPU 结果、Profiler 局部数字或 Probe Anchor 代替正式 GPU 端到端结果。

## 4. 官方 Shape 的处理

- `official/test_shapes.json` 是开发、Runner 和路由共用的唯一 Shape 事实源。
- 公式和语义在所有 Shape 上保持一致，实现可以按 Shape 分流。
- 普通 Sweep 为 `official_01`–`official_13`；Shape 14 共享 Workload、Solution 和 Kernel Registry，但使用独立 `benchmark-streamed`，可以采用保持数学语义的 Batch Streaming 和内存高效 Attention。
- Appendix 未给出的 Dtype 和计时参数属于运行协议，不作为自造 Shape 扩充官方集合。

## 5. 最简判定

> 同一数学函数 + 同一官方接口 + 官方误差通过 + 完整 GPU Forward 实测更快，才是可交付的优化。
