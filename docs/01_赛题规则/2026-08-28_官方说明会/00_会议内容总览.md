## 3. 会议讲了什么

会议内容可以归纳为六条主线：

1. 在参赛者自己的硬件上实现并优化 Transformer Layer，而不是只针对统一评测卡提交一个通用实现。
2. 以 Appendix 的十四个 Shape 为实际测试范围，逐 Shape 检查正确性和性能。
3. 输入、参考计算和精度检查采用 FP32；内部允许使用量化或混合精度，只要最终输出通过精度门槛。
4. Shape 14 是无法依赖完整稠密 Attention Matrix 的极端长序列问题；讲者明确建议分块计算，流式或 Online Attention 是本项目可评估的实现方向，最终仍以官方输出精度检查为准。
5. AI Agent 用于学习、诊断、实现、Benchmark、Profile 和继续迭代；最终仍以正确性后的 Kernel 性能为核心。
6. 提交不仅包含源码，还包含运行说明、技术报告、实际使用的 AI 工具、模型、Skills 和代表性交互过程。

讲者还说明，TikTok 的日常工作会持续优化模型训练和推理中的多种结构，并不局限于 Transformer。本赛题让参赛者在自己的设备上实践同类问题，这为消费级硬件优化提供了直接的业务与工程背景。

## 4. 对本项目最重要的结论

### 已被会议强化的方向

- 以 RTX 4080 作为主要实测设备符合“优化自己的机器”的定位。
- Hardware Probe、Shape 分析、少量候选、真实 GPU 实测和逐 Shape 路由与官方描述的优化循环一致。
- PyTorch 路线足够，无需为了覆盖形式再实现 TensorFlow。
- FP32 外部接口加内部混合精度是允许的优化方式。
- 编译和首次运行可以排除在正式计时之外。

### 需要纠正的方向

- Shape 14 属于完整最终交付范围，需要独立的内存高效执行方案。
- Speedup 和几何平均值仍可用于内部调优，但对外技术结果需要准备逐 Shape MFU，并解释带宽或资源瓶颈。
- 当前基于 SDPA、CUDA Graph 和编译器的路径是有效工程基础，但不能把成熟库能力直接表述为自研 Kernel 创新。
- 官方要求展示 AI 辅助开发过程，但没有要求参赛者必须自建一个通用或专用 Agent Runtime。
- 跨硬件校准是长期价值和 Impact 亮点；比赛主结果可以集中在一张明确披露的 GPU 上。

## 6. 一句话理解

本赛题不是要求把同一份代码搬到任意 GPU 上，而是要求理解特定硬件与不同 Transformer Shape 的瓶颈，在正确性门槛内做可解释的设备专用优化，并清楚展示 AI 如何帮助完成这条实测闭环。
