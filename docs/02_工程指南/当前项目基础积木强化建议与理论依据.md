# 当前项目基础积木强化建议与理论依据

> 评审基线：`main@9395aa84543744e2787c9266ecf409e103e8b40f`  
> 性能基线：用户提供的 `summary.json`，Shapes 1–13 全部通过，Resident 几何平均加速比为 **11.9827×**。  
> 本文只讨论执行层的基础积木（operator、kernel、fusion、precision、runtime），不扩建搜索控制面、Agent 框架或额外治理层。

## 一、结论

当前基础积木已经覆盖了大多数高价值方向：

- Packed QKV；
- PyTorch SDPA、Efficient SDPA、cuDNN SDPA；
- Dh8、S1024/Dh32、S100000/Dh64 专用 Triton Attention；
- QKV 直接写 BHSD、Attention 直接写 BSD；
- Triton Linear + Exact GELU；
- Residual + LayerNorm 融合及 FP32 Residual / FP16 Branch Stream；
- CUDA Graph、Batch-Tiled CUDA Graph、`torch.compile`、Shape 14 Streamed Runtime。

因此，不建议继续横向增加大量通用 Kernel。当前真正值得加强的只有四类：

| 优先级 | 建议积木 | 主要目标 |
|---|---|---|
| P0 | **D=32/128 的 Linear-out + Residual + LayerNorm 融合** | Shapes 1–7、9–13，尤其 Shape 6 |
| P0 | **Shape 14 的 off-diagonal / diagonal Attention 分流** | 减少绝大多数 Key Block 上无效的 causal 非矩阵运算 |
| P1 | **Pre-Norm affine folding** | 从运行时 LayerNorm 中移除 `γ/β` affine |
| P1 | **显式 Flash SDPA 后端** | 将自动分发变成可测、可验证的独立候选 |
| P2（有条件） | **Shape 14 Split-KV** | 仅在 Profiler 证明长 CTA 或尾部不均衡时增加并行度 |

不建议当前投入：

- 自建通用 GEMM 库；
- 为 Shapes 1–12 再写一套通用 Attention；
- Whole-layer Megakernel；
- BF16、FP8 等更多精度分支；
- 继续扩张搜索框架。

## 二、为什么优化重心应放在线性层与边界，而不是继续堆 Attention

令：

\[
M=BS
\]

其中 \(B\) 为 Batch，\(S\) 为序列长度，\(D\) 为隐藏维度，\(F\) 为 FFN 维度，\(L\) 为层数。

每层四类 Linear 的主要 FLOPs 为：

\[
F_{\text{linear}}
=
8MD^2+4MDF
\]

其中：

- QKV：\(6MD^2\)；
- Attention output projection：\(2MD^2\)；
- FFN-in 与 FFN-out：合计 \(4MDF\)。

对 causal self-attention，按有效下三角计算量估计：

\[
F_{\text{attn}}
\approx
2BS^2D
\]

当本赛题中 \(F=D\) 时：

\[
F_{\text{linear}}=12BSD^2
\]

所以两部分占比为：

\[
p_{\text{attn}}
=
\frac{S}{S+6D}
\]

\[
p_{\text{linear}}
=
\frac{6D}{S+6D}
\]

得到：

| Workload | Linear FLOPs 占比 | Attention FLOPs 占比 | 即使 Attention 无限快，整体最大加速 |
|---|---:|---:|---:|
| Shapes 1–6、9–11：\(S=D=128\) | 85.7% | 14.3% | 1.17× |
| Shape 7：\(S=128,D=32\) | 60.0% | 40.0% | 1.67× |
| Shape 8：\(S=128,D=1024\) | 98.0% | 2.0% | 1.02× |
| Shape 12：\(S=32,D=128\) | 96.0% | 4.0% | 1.04× |
| Shape 13：\(S=1024,D=128\) | 42.9% | 57.1% | 2.33× |
| Shape 14：\(S=100000,D=1024\) | 5.8% | 94.2% | 17.28× |

这就是 Amdahl 定律在本项目中的直接约束：

\[
S_{\text{total}}
=
\frac{1}{(1-p)+p/s}
\]

对于 Shape 8，即使把 Attention 完全删除，理论总收益也只有约 2.1%。因此继续为 Shape 8 或 Shape 12 写 Attention Kernel，方向上基本错误。相反，Shape 13 和 Shape 14 才值得继续研究 Attention。

FLOPs 占比不等于实测时间占比，尤其小 Shape 会受 Kernel Launch 主导，但它仍然给出了一个可靠的收益上限，能够阻止低价值优化。

## 三、P0：增加 D=32/128 的 Linear-out + Residual + LayerNorm 融合积木

### 3.1 当前缺口

当前路径已经分别具备：

- `Attention output projection`；
- `FFN-out`；
- `Residual + LayerNorm`。

但执行顺序仍然是：

\[
\text{GEMM}
\rightarrow
\text{写出 update}
\rightarrow
\text{ResidualNorm 重新读取 update}
\rightarrow
\text{写 residual 与 normalized}
\]

也就是说，Attention output projection 与 FFN-out 的结果仍会先物化到 Global Memory，再被下一 Kernel 读取。

当前 `triton_attention_output_projection.py` 只完成 GEMM、bias 和 BHSD→BSD 布局桥；`triton_mixed_residual.py` 则在下一 Kernel 中读取该结果并完成 Residual + LayerNorm。两者之间仍有完整激活张量的写回与重读。

### 3.2 推荐积木

仅针对输出宽度 \(D\in\{32,128\}\)，增加固定语义的：

\[
\boxed{
\text{Linear}
+
\text{Bias}
+
\text{Residual}
+
\text{LayerNorm}
}
\]

数据流应为：

\[
\text{FP32 GEMM accumulator}
\rightarrow
\text{按现有语义舍入为 FP16 update}
\rightarrow
\text{加 FP32 residual}
\rightarrow
\text{计算 mean/variance}
\rightarrow
\text{写 FP32 residual 与 FP16/FP32 normalized}
\]

第一版应显式保留“GEMM 输出先舍入到 FP16，再进入 Residual”的现有精度边界，避免因为融合而偷偷改变数值程序。不要一开始同时开发多套精度语义。

只需要覆盖两个位置：

1. Attention output projection → Residual + `norm2`；
2. FFN-out → Residual + 下一层 `norm1` / `final_norm`。

### 3.3 理论收益

设 branch update 使用 \(u\) 字节存储。每个边界可消除：

\[
uBSD
\]

字节的写出，以及：

\[
uBSD
\]

字节的重新读取。

共 \(2L\) 个边界，因此理论可消除流量：

\[
B_{\text{saved}}
=
4uLBSD
\]

当前主要路径中 update 为 FP16，\(u=2\)，所以：

\[
B_{\text{saved}}
=
8LBSD
\]

对几个 Shape：

| Shape | 可消除的逻辑 update 流量 |
|---|---:|
| Shape 1 / 9 / 10 / 11 | 32 MiB |
| Shape 5 | 64 MiB |
| Shape 6 | **4.88 GiB** |
| Shape 12 | 8 MiB |
| Shape 13 | 256 MiB |

除此之外，还可减少最多 \(2L=8\) 次 ResidualNorm Kernel Launch。

依据 Roofline Model，当算术强度不足时，性能上限由：

\[
P
\le
\min(P_{\text{peak}}, I\cdot BW)
\]

决定。Shape 6 的 GEMM 为极高 \(M\)、较小 \(N=K=128\) 的形状，边界激活流量具有明显价值；小 Shape 则更可能从减少 Launch 获益。

### 3.4 范围控制

不要把该 Kernel 做成通用 Megakernel。

第一阶段仅支持：

- inference；
- all-valid；
- \(D=32/128\)；
- FP16 branch update；
- FP32 residual；
- 当前已存在的 LayerNorm epsilon 与 affine 语义。

原因是：当 \(D\le128\) 时，一个 CTA 可以拥有完整输出行，GEMM accumulator 完成后能在 CTA 内执行行归约；\(D=1024\) 会显著增加寄存器、共享内存与跨 CTA 归约复杂度，不应与第一阶段混在一起。

优先验证顺序：

\[
\text{Shape 6}
\rightarrow
\text{Shapes 5/1/12}
\rightarrow
\text{Shape 13}
\]

若 Shape 6 和至少一个小 Shape 的端到端收益均低于 3%，应停止继续泛化。

## 四、P0：强化 Shape 14 Attention 内核的 off-diagonal / diagonal 分流

### 4.1 当前缺口

当前 Shape 14 Kernel 对每一个 Key Block 都执行：

- causal position compare；
- 多个逻辑 `and`；
- `where(..., -inf)`；
- masked probability 修正。

但对某个 Query Tile：

\[
Q_i=[iB_M,(i+1)B_M)
\]

若 Key Tile：

\[
K_j=[jB_N,(j+1)B_N)
\]

满足：

\[
(j+1)B_N \le iB_M
\]

那么整个 Key Tile 都位于所有 Query 位置之前，整块天然 causal-valid，无需逐元素 causal mask。

当前实现把“完全位于对角线下方的块”和“与对角线相交的块”放在同一个循环中，导致绝大多数循环都执行了不必要的非矩阵运算。

### 4.2 推荐改造

把循环拆成两段：

1. **off-diagonal 区域**：完整有效，不执行 causal mask；
2. **diagonal 区域**：只对少量与对角线相交的块执行 mask。

每个 Query Tile 中，需要 mask 的 Key Tile 数量约为：

\[
O\left(\left\lceil\frac{B_M}{B_N}\right\rceil+1\right)
\]

而总 Key Tile 数量随序列增长为：

\[
O\left(\frac{S}{B_N}\right)
\]

因此当 \(S=100000\) 时，绝大多数迭代都可以进入无 mask 的快速路径。

该改造：

- 不增加中间 Tensor；
- 不改变 Online Softmax；
- 不改变 HBM 访问规模；
- 不需要新的搜索维度；
- 只减少非矩阵指令和分支；
- 与 FlashAttention-2“减少 non-matmul FLOPs”的原则一致。

### 4.3 可同时考虑的精确 Scale Folding

Shape 14 的：

\[
d_h=64
\]

所以：

\[
\frac{1}{\sqrt{d_h}}=\frac18=2^{-3}
\]

这是二进制中的精确幂次缩放。可以只把 \(1/8\) 折叠到 Q Projection 权重中，同时保留 `exp2` 所需的 \(\log_2 e\) 转换。

该项属于低成本附加实验，不应先于 off-diagonal / diagonal 分流。

## 五、P1：增加 Pre-Norm affine folding

LayerNorm 可写为：

\[
\operatorname{LN}(x)
=
\hat{x}\odot\gamma+\beta
\]

其中：

\[
\hat{x}
=
\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}
\]

若后接 Linear：

\[
y=W(\hat{x}\odot\gamma+\beta)+b
\]

则可以预先变换为：

\[
W'=W\operatorname{diag}(\gamma)
\]

\[
b'=b+W\beta
\]

运行时只计算：

\[
y=W'\hat{x}+b'
\]

本项目可折叠：

- `norm1 → qkv_proj`；
- `norm2 → ffn_in`。

`final_norm` 没有下游 Linear，不能折叠。

该变换可以移除运行时 LayerNorm 中的：

- \(\gamma\) 与 \(\beta\) 读取；
- 一次逐元素乘法；
- 一次逐元素加法。

但它不会消除 normalized 激活的写回，也不会减少 Kernel 数，所以预期收益低于上一节的边界融合。它适合作为一个固定、可搜索的派生权重候选，不需要设计通用 Weight Transform Graph。

实数域中该变换严格等价；浮点数中运算顺序改变，因此仍须通过当前官方 comparator 与 Formal Promotion。

## 六、P1：补上显式 Flash SDPA 积木

当前项目具有：

- 自动 `causal_sdpa`；
- 强制 Efficient SDPA；
- 强制 cuDNN SDPA；

但没有强制 Flash Attention 候选。

PyTorch 的 `sdpa_kernel()` 已支持显式选择 `FLASH_ATTENTION`。建议增加一个严格后端：

\[
\texttt{FP16\_FLASH\_SDPA}
\]

只在以下条件启用：

- CUDA；
- inference；
- causal；
- all-valid；
- FP16 Q/K/V；
- 支持的 head dimension 与 stride。

若自动 SDPA 本来就选择同一个 Flash Kernel，它可能没有性能收益；它的价值是让搜索结果和执行签名明确表达实际后端，并避免不同 PyTorch / GPU 平台上的自动分发变化。

最值得观察的是 Shape 13。Shapes 1–12 的 Attention FLOPs 占比大多较低，不应因为新增该候选而继续扩写通用 Attention Kernel。

## 七、P2：Shape 14 Split-KV 只作为有条件积木

当前 Shape 14 每个 Query Tile 由一个 Program 顺序扫描此前全部 Key Tile。若 Profiler 显示：

- late-query CTA 执行时间很长；
- Wave 尾部明显；
- SM Active 较低；
- 单 CTA 关键路径成为限制；

可以把 Key 轴拆为少量 Partition。

每个 Partition 计算 Online Softmax 局部状态：

\[
(m_r,l_r,a_r)
\]

其中：

- \(m_r\)：局部最大值；
- \(l_r\)：局部归一化和；
- \(a_r\)：局部未归一化输出累加器。

多个 Partition 可按下式精确合并：

\[
m=\max_r m_r
\]

\[
l=\sum_r e^{m_r-m}l_r
\]

\[
a=\sum_r e^{m_r-m}a_r
\]

\[
o=\frac{a}{l}
\]

这是 Online Softmax 状态的结合律形式，数学上不需要近似。

但 Split-KV 会增加：

- 局部状态写回；
- 第二阶段归约；
- Kernel Launch；
- 额外显存流量。

因此不能默认认为更快。只搜索：

\[
R\in\{1,2,4\}
\]

已经足够。若 off-diagonal / diagonal 改造后 Profiler 没有暴露并行度问题，则不实现。

## 八、当前不应加强的积木

### 8.1 不自建通用 GEMM 库

Shape 8 中 Linear FLOPs 占比约 98%，当前赢家却是 `torch.compile(max-autotune)` 配合成熟 GEMM 后端。这说明大尺寸 GEMM 的正确方向仍是 vendor library / compiler template，而不是再写一套通用 Triton GEMM。

若 Profiler 显示 Shape 8 的 GEMM 明显低于合理 Roofline，只测试一个 cuBLASLt/CUTLASS 候选即可；不要建立自己的多算法 GEMM 框架。

### 8.2 不再为 Shapes 1–12 写通用 Attention

除 Shape 7 的 Dh8 特化外，大部分 Shape 的 Attention 理论占比太低。Amdahl 上限已经说明，即使 Attention 无限快：

- Shape 8 仅约 1.02×；
- Shape 12 仅约 1.04×；
- 常规 \(S=D=128\) Shape 仅约 1.17×。

现有 Dh8 专用 Kernel 已经覆盖了 head dimension 极小、库 Kernel 容易低效的例外。

### 8.3 不增加更多精度格式

当前 13 个 Resident Shape 全部通过，最大 tolerance ratio 仍小于 1。现阶段继续加入 BF16、TF32、FP8 会扩大搜索空间，却没有明确性能缺口对应它们。

等项目迁移到 Hopper、Blackwell 或 AMD 平台后，再按硬件原生精度能力增加候选。

### 8.4 不增加新的搜索层与 Agent 层

当前固定预算结构筛选、Branch-local TPE、Shape 14 无放回枚举、Formal Paired Promotion、Evidence Identity 和 Deployment Registry 已经足够。剩余性能问题来自可执行程序积木，而不是控制面缺失。

## 九、最小实施顺序

### 第一步：只做四个代表 Shape 的 Profiler

- Shape 6：大 \(M\)、小 \(N/K\)，检查带宽和边界流量；
- Shape 8：大 GEMM，检查 Tensor Core 与 GEMM Roofline；
- Shape 13：检查 SDPA / Attention 占比；
- Shape 14：检查 non-matmul 指令、CTA 尾部和 SM 利用率。

### 第二步：实现 D=32/128 Linear-out Boundary Fusion

先验证 Shape 6，再验证小 Shape。若没有稳定的端到端收益，立即停止扩展。

### 第三步：优化 Shape 14 当前 Kernel 本身

先做 off-diagonal / diagonal 分流，再重新搜索现有 Tile、Warp、Stage、Microbatch。不要先上 Split-KV。

### 第四步：补充两个低成本候选

- Pre-Norm affine folding；
- Forced Flash SDPA。

### 第五步：按 Profiler 决定是否实现 Split-KV

没有证据时不实现。

---

## 十、最终建议

当前项目不缺“更多种类的积木”，而缺两块更接近性能下界的积木：

\[
\boxed{
\text{Resident：输出 GEMM 与 ResidualNorm 的真正边界融合}
}
\]

\[
\boxed{
\text{Shape 14：减少 causal online attention 中的非矩阵工作}
}
\]

其余改进应保持小范围、可否证：

- 一个候选；
- 一个明确理论上限；
- 一组代表 Shape；
- 一次 Formal paired test；
- 达不到 3%–5% 端到端收益即停止。

这比增加更多 Backend 枚举、Kernel 文件或 Agent 流程更适合把项目继续发展为长期个人代表作。
