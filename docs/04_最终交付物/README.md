# 最终交付物导航

本目录是中文交付材料的唯一入口。它负责帮助评委快速理解项目、核对官方要求并找到权威证据，不复制源码、完整技术细节或机器可读结果。

## 3 分钟阅读顺序

1. [项目说明](./01_项目说明.md)：先了解问题、核心洞察、方案与实际价值。
2. [结果摘要](./05_结果摘要.md)：查看主要正确性、性能和资源结果及其证据边界。
3. [技术报告](./02_技术报告.md)：理解架构、关键取舍、自主贡献与第三方能力边界。
4. [AI 协作说明](./03_AI协作说明.md)：了解实际使用的工具、模型、人类引导和代表性交互。
5. [运行与结果复现](./04_运行与结果复现.md)：找到最短运行方式和完整复现入口。
6. [提交清单](./06_提交清单.md)：提交前核对仓库、Devpost、报告和视频要求。

如果只需要核验事实，可直接查看：

- [项目根 README](../../README.md)
- [英文完整技术报告](../../TECHNICAL_REPORT.md)
- [RTX 4080 最终机器可读结果](../../results/final/nvidia_geforce_rtx_4080.json)
- [RTX 4080 已验证硬件包](../../verified_hardware/nvidia_geforce_rtx_4080/README.md)

| 文件 | 主要回答的问题 |
| --- | --- |
| `01_项目说明.md` | 为什么这个问题重要，本项目如何直接解决它，有什么可感知价值？ |
| `02_技术报告.md` | 系统如何实现，哪些部分由项目完成，关键决策依据是什么？ |
| `03_AI协作说明.md` | AI 实际参与了什么，人类如何约束和验证其工作？ |
| `04_运行与结果复现.md` | 需要什么环境，如何运行、复现和定位权威产物？ |
| `05_结果摘要.md` | 当前结果是什么，指标如何理解，哪些结论不能外推？ |
| `06_提交清单.md` | 官方交付项是否齐全，提交前还需检查什么？ |

## 与官方要求的对应关系

| 官方要求 | 对应材料 |
| --- | --- |
| 清晰的项目说明与问题回应 | `01_项目说明.md`、项目根 README |
| 结构清晰、可运行的完整源码 | 项目根目录中的 `solution/`、`runner/`、`official/` 和 `tests/` |
| Setup、安装、运行与结果复现 | `04_运行与结果复现.md`、项目根 README |
| 运行环境、方法、正确性、性能与局限 | `02_技术报告.md`、英文完整技术报告 |
| AI 工具、模型、实际 Skills、人类引导与交互历史 | `03_AI协作说明.md` |
| 最终结果与逐 Shape 证据 | `05_结果摘要.md`、最终机器可读结果 |
| Public Repository、Devpost 与其他提交项 | `06_提交清单.md` |
| Demo Video | 已完成三分钟叙事、逐页内容、英文讲稿和视觉规范规划；可编辑 PPT、录制成品与公开链接待生成 |

## 信息边界

- 源码以项目根目录为准，本目录不保存源码副本。
- 完整英文技术叙事以根目录 `TECHNICAL_REPORT.md` 为准。
- 数值结果以 `results/final/nvidia_geforce_rtx_4080.json` 为准；摘要只负责解释和导航。
- AI 协作材料只记录实际发生的工作，不把未来 Agent 设计写成已完成能力。
- 赛题原文、会议内容和开发规划分别保留在 `docs/01_赛题规则`、`docs/02_开发路线` 和 `docs/03_Agent系统`，不混入评委主线。
