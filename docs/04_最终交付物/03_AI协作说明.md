# AI 协作说明

## 1. 协作原则

> 本项目把 AI 用作受约束的研发协作者，而不是运行时组件或性能裁判：人类负责定义赛题合同、硬件目标、工程取舍与证据边界；Codex 负责分析代码、提出假设、实现候选和组织测试；确定性 Runner 负责正确性比较、实际执行路径确认、GPU 计时与路由发布，最终是否保留方案由实测结果决定。

这套分工使 AI 能够加快知识获取、代码迭代和方案探索，同时避免让模型推测替代可复现的工程事实。AI 提出的候选不能直接成为正式策略；只有通过 Comparator、Observed Execution 检查和目标 GPU 测量的方案，才能进入已验证路由。

## 2. 实际使用的工具与能力边界

| 项目 | 实际使用情况 |
| --- | --- |
| AI 编程工具 | OpenAI Codex Desktop，用于阅读仓库、修改代码与文档、运行 PowerShell 和 Git 命令、协调有限的并行审计，以及解释确定性 GPU 结果。 |
| LLM | GPT-5-based Codex model。仓库没有为每次开发会话持久保存稳定的点版本别名，因此本文不推测或虚构更具体的模型名称。 |
| 运行时 AI API | 无。Benchmark、校准流程和部署后的 Dispatcher 均不调用 LLM 或外部 AI 服务。 |
| Project-local Agent Skill | 无。已验证优化过程使用面向具体任务的直接指令，没有打包或声称使用独立的项目内 Skill。规划中的 Device、Profile 和 Kernel Skill 属于未来 Agent 设计，不作为本次已使用的交付物。 |

“没有 project-local Skill”是对实际过程的完整披露，而不是需要补造的目录。Codex 内置的仓库、Shell 和有限多 Agent 协作能力属于工具功能，不冒充项目自行编写并用于 Kernel 优化的 Competition Skill。

## 3. 人类如何指导 AI

人类持续向 Codex 提供以下信息和约束：

1. 以官方 Transformer、已公布的 14 个 Shape、FP32 外部语义和误差阈值为计算合同。
2. 以 NVIDIA GeForce RTX 4080 为当前正式结果设备，性能判断必须来自真实 GPU 测量；CPU 运行和理论排序不能替代最终证据。
3. 优先推进可测量的性能主线，避免用庞大的验证体系、结果数据库或通用 Agent 基础设施分散精力。
4. 对不同 Shape 分析真实瓶颈；距离现有方法上限较远时允许采用新的执行方法，已有明确路线时优先做工程细化。
5. 清楚区分项目自写 Triton Kernel、PyTorch/cuDNN/cuBLAS 等库原语，以及只具备 provisional 证据的结果。
6. 重构时删除已经被替代的架构，不为了兼容旧设计继续维护重复的 Policy、资格判断和隐藏控制通道。

Codex 在这些边界内提出瓶颈假设、候选策略和代码改造。确定性程序负责 Comparator、Observed Execution、CUDA Event Timing 和 Route Promotion；人类结合代码可读性、正确性、资源使用和实测收益决定保留、缩小适用范围或删除候选。

## 4. 五个代表性交互案例

下列内容是对真实开发过程的脱敏摘要。它们保留“人类约束 → AI 协作 → 确定性证据 → 工程决定”的完整链路，但不复刻原始聊天。

### 4.1 从固定设备结论到硬件感知冷启动

**人类判断。** 人类指出，把 RTX 4080 的赢家直接写死为通用路由无法支持新设备；新硬件应先建立硬件画像，再用理论模型缩小候选范围，由真实 GPU 复测产生并自动发布本设备赢家。人类同时指出，若系统总是选择排序最高者，面向用户展示一个没有决策用途的“置信度”并无价值。

**AI 协作。** Codex 重构了 Hardware Probe、候选资格、理论排序、Calibration 和 Formal Route Promotion，使探针先提供硬件事实，排序模型只生成有限候选，GPU 测量决定最终路由。

**证据与决定。** 当前冷启动流程不会把理论第一名直接当作赢家；Smoke 用于筛除不可用路径，Formal 的完整 Forward 正确性和延迟结果负责精确路由发布。相关实现见 [Calibration Service](../../runner/calibration.py)、[Hardware Router](../../runner/hardware_router.py) 和提交 [`d257a4a`](https://github.com/Wendystar0628/AI-Assisted-Shape-Aware-Transformer-Kernel-Optimizer/commit/d257a4a)。

### 4.2 将冗余运行记录压缩为一个正式结果

**人类判断。** 人类检查旧结果目录后指出，其中大量字段和重复文件既不能帮助后续调优，也不利于 Agent 或评委快速读取，要求只保留主线性能、正确性、实际策略和必要资源数据。

**AI 协作。** Codex 将对外结果整合为“每个硬件身份一个最终 JSON”，把可重新生成的探索性实验隔离到 Intermediate 区域，并统一 Resident 与 Streamed Scope 的字段口径。

**证据与决定。** 当前权威记录 [RTX 4080 最终结果](../../results/final/nvidia_geforce_rtx_4080.json)集中保存逐 Shape Median/P90、Speedup、正确性、Useful TFLOP/s、项目估算 MFU、峰值显存和实际 Policy；结果边界见 [Results Contract](../../results/README.md)。对应提交为 [`0b08a6a`](https://github.com/Wendystar0628/AI-Assisted-Shape-Aware-Transformer-Kernel-Optimizer/commit/0b08a6a)。

### 4.3 迁移官方 14 个 Shape，并为 Shape 14 建立独立机制

**人类判断。** 官方发布新版 Benchmark 和 14 个测试 Shape 后，人类要求彻底迁移并删除旧 Workload 设计。对于 `B=32, D=1024, H=16, S=100000, L=2` 的 Shape 14，人类进一步提出不应把容量受限问题与普通 Resident Shape 混在同一流程中。

**AI 协作。** Codex 将 [官方 Shape](../../official/test_shapes.json)设为唯一 Workload 来源，并在 [Workload Execution](../../runner/workload_execution.py)中区分 Resident 与 Batch-streamed 模式。Shape 14 由 [Streamed Executor](../../runner/streamed_execution.py)筛选合法 Policy 和 Microbatch 组合，避免构造完整逻辑 Batch 的稠密 `S×S` Attention Matrix。

**证据与决定。** Shape 14 完成全部 32 个样本的逻辑 Workload：Target Median 为 **17.085411 s**，峰值设备分配为 **7.307 GiB**，Achieved Performance 为 **81.4299 useful TFLOP/s**。该结果没有可执行的稠密完整 Baseline，因此不声明 Speedup，并明确标记为 **provisional、Target-only**。迁移与实现对应提交 [`37a4d94`](https://github.com/Wendystar0628/AI-Assisted-Shape-Aware-Transformer-Kernel-Optimizer/commit/37a4d94)和 [`59a10b5`](https://github.com/Wendystar0628/AI-Assisted-Shape-Aware-Transformer-Kernel-Optimizer/commit/59a10b5)。

### 4.4 从调参数转向 Shape 专用执行方法

**人类判断。** 人类要求先判断当前性能与理论上限的距离：对多轮工程调参仍远离合理上限的 Shape，应探索新的执行方法；对已有高性能赢家则继续保护，不允许激进候选破坏现有路由。

**AI 协作。** Codex 为 Shape 5 组合 FP16 Shadow Weights、Efficient SDPA、混合 Residual-Norm Triton Kernel、基于 Tensor Identity/Version 的 Unchanged-input Staging 与 CUDA Graph；为高 Batch Shape 6 组合 Batch-tiled CUDA Graph、FP16 Shadow Weights、自研 Initial FP16 LayerNorm 和 Mixed Residual-Norm；为 Shape 8 保留 FP32 主权重并提供派生、非持久化 FP16 Shadow Weights；为 Shape 11 实现直接输出 BSD Layout 的 `head_dim=8` Triton Causal Attention；为长序列 Shape 13 实现 Online Causal Attention Triton Kernel。专用实现见 [Mixed Residual-Norm Kernel](../../solution/kernels/triton_mixed_residual_norm.py)、[Initial Norm Kernel](../../solution/kernels/triton_initial_norm.py)、[Shape 11 Attention Kernel](../../solution/kernels/triton_dh8_attention.py)和 [Shape 13 Attention Kernel](../../solution/kernels/triton_shape13_attention.py)。

**证据与决定。** RTX 4080 Formal 结果中，Shape 5、6、7、8、11、13 的 Median Speedup 分别约为 **9.290x、12.347x、23.237x、2.291x、27.355x、40.122x**；13 个 Resident Shape 均通过五次 Comparator Trial。库 GEMM、cuDNN 和 Efficient SDPA 继续归属于其提供者，只有明确列出的 Triton 代码作为项目自写 Kernel。相关迭代见提交 [`0f2871c`](https://github.com/Wendystar0628/AI-Assisted-Shape-Aware-Transformer-Kernel-Optimizer/commit/0f2871c)、[`cf10787`](https://github.com/Wendystar0628/AI-Assisted-Shape-Aware-Transformer-Kernel-Optimizer/commit/cf10787)和 [`c75dc66`](https://github.com/Wendystar0628/AI-Assisted-Shape-Aware-Transformer-Kernel-Optimizer/commit/c75dc66)，当前实测数字以 [RTX 4080 最终结果](../../results/final/nvidia_geforce_rtx_4080.json)为准。

本轮还让独立的 GPT-5.6 Sol Pro 对完整仓库和性能结果提出外部审视意见，再由 Codex 的并行子任务把建议转为隔离候选，并统一交给真实 GPU A/B。该过程保留了通过阈值的 Shape 5 Graph Staging 和 Shape 8 FP16 Shadow Weights，同时否决了更慢的 Shape 6 Tile 256、Shape 13 cuDNN/替代 Triton 配置；当前 Windows PyTorch 未编译 Flash Attention，因此相应候选被记录为环境不可用，而不是包装成负性能结论。AI 的作用是扩大假设空间和加速实现，最终决策仍由可复现的正确性与完整 Forward 延迟决定。

### 4.5 删除旧架构，建立可解释的唯一事实来源

**人类判断。** 人类发现 Policy、候选、路由资格和实际执行曾分散在多个模块，并明确要求在保留工程流程的前提下删除旧架构，不维持重复名单和兼容层，也不以复杂插件系统替代一个可以简单解决的问题。

**AI 协作。** Codex 将 Policy 定义集中到 [Policy Registry](../../policy_registry.py)，用 [Immutable Execution Plan](../../solution/execution_plan.py)一次解析 Policy、Shape、Dtype、设备和后端资格，让 Forward 与路径说明消费同一个决定，并统一 Route Contract 与 Observed Execution 证据。

**证据与决定。** 当前公开主线不再保留旧 Policy 清单的兼容副本；架构测试检查 Registry、Execution Plan、Route Identity 和实际执行路径之间的边界。主要重构对应提交 [`9ba848b`](https://github.com/Wendystar0628/AI-Assisted-Shape-Aware-Transformer-Kernel-Optimizer/commit/9ba848b)，相关测试见 [Architecture Contracts](../../tests/architecture/test_architecture_contracts.py)。

## 5. 隐私与证据声明

本文提供的是连续决策链的忠实摘要，不是逐字聊天记录。最终提交不包含系统提示、账户信息、API Key、私人目录、未公开凭据或与项目无关的对话。

证据按职责分开：

- Git Commit 用于说明相应代码和架构变化；
- [最终性能结果](../../results/final/nvidia_geforce_rtx_4080.json)用于说明当前 RTX 4080 的测量事实；
- [技术报告](../../TECHNICAL_REPORT.md)用于说明环境、协议、方法、性能解释和局限；
- 代码中的 Observed Execution 与 Formal Comparator 用于防止未实际执行的候选冒充优化成功。

这些证据不用于反向推测未保存的模型点版本，也不把规划中的 Skill 或 Agent Runtime 写成已实现成果。当前竞赛实现的正确性、计时、校准和在线路由均由确定性代码完成；AI 协作的价值体现在提出和实现候选、加速分析，以及在人类约束和 GPU 反馈下持续收敛。
